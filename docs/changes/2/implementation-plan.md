# 实施计划：omp 来源从读取到三份输出的完整流程（Issue #2）

> 状态：已于 2026-10-02 获发起人批准。

## 依据

SDD `docs/changes/1/sdd.md`（结构、统一记录、omp 映射、分块、模型运行器、事件与事项、输出与工作目录）；SRS `docs/changes/1/srs.md` 的 D2–D18 和 D1 中 omp 的部分。

## 工作模式

`tdd`：这是新写的正常代码，纯函数模块逐片先写失败的测试再实现。

SDD 中两处未经原型验证的设计（在用户消息处分块并附带前文事件、按规则判定事项状态）按 SDD 实现，并在实现完成后用本机真实的一天各观察一次，观察结果写进实现结果的交审消息。观察到与 SDD 的推翻条件相符的情况时停下交发起人决定，不自行改设计。

## 改哪几个文件、每处怎么改

全部为新增，除最后两行。

| `src/select.ts` | 按本地时区自然日筛选；同一来源内按记录标识去重 |

| `src/extract.ts` | 事件抽取的提示词；逐行解析回复；拒绝无引用、引用不存在或格式损坏的事件；按引用类别复核证据等级；从第二块起附带本会话此前的事件陈述 |
| `src/merge.ts` | 事项归并的提示词；逐行解析；拒绝不存在的事件编号；找出未归并和被多次归入的事件 |

| `src/coverage.ts` | 覆盖台账：各步骤记数，计算未被引用的用户消息和最大事项占比，产出覆盖清单 |
| `src/probe.ts` | 探测已知但未支持的客户端的默认记录目录（首版只有 Codex CLI） |

| `test/helpers.ts` | 在临时目录里从零生成合成的 omp 记录文件的辅助函数；模型运行器的替身 |

## 测试挂哪

接缝是各模块的导出函数，输入为合成记录，模型运行器换成返回固定文本的替身。自动测试不调用真实模型，不读取真实会话。

| 测试文件 | 用例（对应 SRS） |
|---|---|
| `test/omp.test.ts` | 各类记录的映射；多级子 agent 目录；坏行计数；读取失败不中断；路径超过 260 字符的文件能读取（仅在 Windows 上运行）（D2、D5、D6） |
| `test/select.test.ts` | 本地时间 23:59:59.999 属于当天、00:00:00.000 属于次日；无时间戳记录只计数；重复标识只留一条（D3） |
| `test/digest.test.ts` | 成功的工具调用只有一行；报错的带头尾；思考不送；压缩只留标记；其余类型进计数（D6） |
| `test/chunk.test.ts` | 总量等于块大小时一块、超过一个字符时两块；切点落在用户消息之前；单段超长时段内切（D7） |
| `test/extract.test.ts` | 引用全部存在则接受、有一个不存在则拒绝；坏行只损失该行；有成功工具调用支撑为有证据、只有助手文字为仅自述；第二块的提示词含前文事件（D9–D11） |
| `test/model.test.ts` | 首次失败后重试成功；两次都失败时返回失败；相同提示词第二次命中缓存不再调用（D8、D12） |
| `test/merge.test.ts` | 未归并事件被找出；不存在的事件编号被拒（D13） |
| `test/status.test.ts` | 规则表每一行各一条用例，含「完成后又取消」「失败后又完成」两组顺序对照 |
| `test/cli.test.ts` | 用替身跑通一天，产出三份文件且内容与合成输入对应；调用失败的会话在概览里点名；没有输出目录时报错；输出目录在代码仓库内时拒绝；输出目录里没有摘录和模型往来（D4、D12、D14、D17、D18） |

执行时机：
- 每片先运行相关的那个测试文件（`bun test test/<名>.test.ts`），看到失败再实现。
- 每个模块完成后运行全套 `bun test` 和类型检查 `bun run typecheck`。
- 全部完成后在 Windows 本机对真实的一天运行一次：核对三份输出齐全、覆盖清单各项存在、运行前后 omp 会话目录的记录文件数相同、同一天再跑一次时全部命中缓存。这一步调用真实模型，产出写到私有报告仓的工作副本，不进本仓库。

`prototype/proto.ts`、`docs/changes/1/` 下的两份文档、`LICENSE`；不实现 Claude Code 适配器（#3）；不做 macOS 上的任何操作（#4）；不替使用者提交或推送报告仓。
