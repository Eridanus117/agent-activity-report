# 实施计划：Claude Code 来源适配器（Issue #3）

> 状态：已于 2026-10-03 获发起人批准。

## 依据

SDD `docs/changes/1/sdd.md` 的「Claude Code 映射」和「按天筛选与去重」（2026-10-03 按核实结果修订，修订部分与本计划一并待审）；SRS D1、D2、D6。

## 工作模式

`tdd`：新适配器和去重顺序的改动都是正常代码，逐片先写失败的测试再实现。三处未知已用只读统计核实，结论写在 SDD，不再另做原型。

## 改哪几个文件、每处怎么改

| 文件 | 怎么改 |
|---|---|
| `src/sources/claude-code.ts`（新增） | 定位 `~/.claude/projects` 下的主会话和 `subagents/` 文件；按修订后的映射表翻译成统一记录；会话标题取最后一条 `ai-title`；超长路径处理与 omp 相同 |
| `src/types.ts` | 引用信息加上来源名，使明细里的来源定位能区分两个客户端 |
| `src/digest.ts` | 把来源名带进引用信息 |
| `src/cli.ts` | 新增 `--source`（默认两个来源都读）和 `--claude-root`；读完全部文件后按每个文件最早记录的时间排序，再依次筛选和去重；会话标识带上来源前缀；覆盖清单的「受支持来源」列出两项，说明文字改为实际情况 |
| `src/render.ts` | 来源定位前加来源名；概览「已读取的来源」按实际启用的来源列出 |
| `test/helpers.ts` | 增加从零构造 Claude Code 形状记录的辅助函数 |
| `test/claude-code.test.ts`（新增） | 见下节 |
| `test/cli.test.ts` | 增加两个来源同时运行、跨文件复制去重归属、`--source` 只选一个来源的用例；调整受影响的现有断言（来源列表、来源定位格式） |
| `README.md` | 状态一节写明支持 Claude Code，并注明核实所依据的客户端版本范围 |

## 测试挂哪

模型调用仍用替身；只用合成记录。

| 测试文件 | 用例 |
|---|---|
| `test/claude-code.test.ts` | 人工输入成为用户消息；没有 `origin` 的旧版输入成为用户消息；任务通知、`isMeta`、命令输出不成为用户消息；斜杠命令还原为「/命令 参数」；用户中断成为停止；续接摘要只留标记；`queued_command` 附件中 `prompt` 类成为用户消息、任务通知类不成为；工具结果并入调用并区分成功与报错；`AskUserQuestion` 带回答；思考不送；`pr-link` 成为成功的工具行；子 agent 文件归入主会话且其输入不算用户消息；坏行计数；读取失败不中断 |
| `test/cli.test.ts` | 两个来源都有当天记录时三份输出都包含两者，覆盖清单分别列出；同一 `uuid` 出现在两个会话文件时只保留一条，且留在较早开始的会话里；`--source omp` 时不读 Claude Code |

执行时机：每片运行相关测试文件；适配器和 cli 改动各完成后运行全套 `bun test` 和 `bun run typecheck`。全部完成后在本机对一个同时有 omp 和 Claude Code 记录的真实日子运行一次，核对覆盖清单中两个来源的处理状态和去重数；这一步调用真实模型，产出不进本仓库。

## 不动什么

omp 适配器的映射、抽取和归并提示词、状态规则、输出文件的种类；不做 macOS 上的任何操作（#4）；不支持 Codex CLI。
